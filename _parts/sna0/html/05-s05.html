0.5 R – csak ahol muszáj ★

A könyv adatai már R nélkül is megvannak. R-re mégis szükség lesz: néhány módszernek egyszerűen nincs érett Python-megvalósítása. Ebben a részben megnézzük, melyek ezek, egyszer feltelepítjük az R-t, és arra is felhasználjuk, hogy a Python-exportunkat egy független úton ellenőrizzük.

Útiterv:

  1. Mikor kell R? A kurzus R-es pontjai.
  2. Telepítés: R, a könyv csomagja, és a buktató, amelybe mi is belefutottunk.
  3. Ellenőrzés és előkészület: R-es export összevetése, statnet és RSiena a 16. leckéhez.

Hüvelykujjszabály: az R a kurzusban eszköz, nem munkakörnyezet. Az adat CSV-ben utazik a két nyelv között, és minden, ami Pythonban is megy, Pythonban készül.

Példa 1 – ugyanaz a szám R-ben Ha az R és az xUCINET már fent van (2. lépés), a Padgett-féle házassági háló sűrűsége: 
Rscript -e 'library(xUCINET); xDensity(Padgett_FlorentineFamilies$Marriage)'
  .  ------------------------------------------------------------------
  .   Number of valid cells: 240
  .   which corresponds to: 100 % of considered cells.
  .  ------------------------------------------------------------------

[1] 0.1666667
Az xDensity előbb kiírja, hány cellát vett figyelembe ($16 \cdot 15 = 240$, az átló nélkül), aztán az eredményt. Kézzel: 16 család $16 \cdot 15 / 2 = 120$ párt alkot, ebből 20 között van házasság, $20/120 = 1/6 \approx 0{,}167$. (A sűrűséget a 10. lecke tárgyalja. Itt csak azt látjuk, hogy az R ugyanazt az adatot olvassa, mint mi.)

2. lépés: telepítés

Telepítés Ubuntu 24.04-en

1. Friss R a CRAN Ubuntu-tárából, és egy rendszerkönyvtár (az igraph R-csomag lefordított része a GLPK-t használja). Az Ubuntu saját R-je túl régi (lásd a buktatókat), ezért előbb a CRAN tárolóját vesszük fel (a CRAN hivatalos útmutatója szerint):

sudo apt install --no-install-recommends software-properties-common dirmngr
wget -qO- https://cloud.r-project.org/bin/linux/ubuntu/marutter_pubkey.asc \
  | sudo tee -a /etc/apt/trusted.gpg.d/cran_ubuntu_key.asc
sudo add-apt-repository "deb https://cloud.r-project.org/bin/linux/ubuntu $(lsb_release -cs)-cran40/"
sudo apt install --no-install-recommends r-base libglpk40
R --version | head -1
R version 4.6.2 (2026-10-29) -- "Diversified Portfolio"

2. Bináris csomagtár. A CRAN Linuxra csak forráscsomagot ad, ezért minden csomag percekig fordulna. A Posit Public Package Manager (P3M) előre lefordított változatokat ad, ha az R elküldi a saját verzióját és platformját. Ez a Python-kerekek R-es párja. Írd ezt a ~/.Rprofile fájlba:

options(repos = c(CRAN = "https://p3m.dev/cran/__linux__/noble/latest"))
options(HTTPUserAgent = sprintf("R/%s R (%s)", getRversion(),
  paste(getRversion(), R.version["platform"], R.version["arch"], R.version["os"])))

3. A könyv csomagja és a függőségei (a projekt gyökeréből, ahol a data/raw/ van):

Rscript -e 'install.packages(c("sna", "igraph", "blockmodeling", "FactoMineR"))'
Rscript -e 'install.packages("data/raw/xUCINET_0.0.2.0020.tar.gz", repos = NULL, type = "source")'

A repos = NULL, type = "source" azt mondja: ne a netről, hanem ebből a fájlból telepíts. Az xUCINET tiszta R-kód, nem kell fordítani. (Kipróbáltuk egy tiszta Ubuntu 24.04-en: a fenti lépésekkel 123 csomag települt binárisként, csak az xUCINET forrásból.)

B-terv: Docker Ha nem akarod a gépedre telepíteni az R-t, egy kész R-képben is futtathatod (mi is így ellenőriztük): docker run --rm -it -v "$PWD:/work" -w /work rocker/r-ver:4.5 bash, benne apt-get update && apt-get install -y libglpk40, és utána ugyanazok az Rscript parancsok. A rocker-kép a P3M-et már be is állította.
Buktatók (az első kettőbe mi is belefutottunk)
  • libglpk.so.40: cannot open shared object file az xUCINET telepítésekor: a hiba az igraph R-csomag betöltésénél jön, mert a GLPK-könyvtár hiányzik. Javítás: sudo apt install libglpk40, és telepítsd újra. (Ha a csomagok forrásból fordulnak, a libglpk-dev kell.)
  • package 'RSiena' is not available for this version of R: az Ubuntu 24.04 saját r-base-e az R 4.3.3, az RSiena 1.6.6 viszont R ≥ 4.5.0-t kér. Ezért kell a CRAN tárolója (1. pont). Az xUCINET és a statnet a régi R-rel is települne, ezért a hiba csak a 16. leckénél derülne ki.
  • package 'xUCINET' is not available: a könyv szerinti install.packages("xUCINET") a CRAN-on keresi, ahol nincs. A letöltött fájlból telepíts (fent).
  • Kis- és nagybetű. library(xUCINET), nem library(xucinet). Az utóbbi a GitHubos 2.0, egy másik csomag.
  • Lassú telepítés, „installing *source* package”. Ha a P3M nem bináris csomagot ad, hanem forrást, akkor hiányzik vagy hibás a HTTPUserAgent beállítás, vagy a tár URL-je nem a te Ubuntu-verziódhoz tartozik (noble = 24.04, jammy = 22.04).

3. lépés: ellenőrző export, statnet és RSiena

Most, hogy fent van az R, egy fontos ellenőrzést is el tudunk végezni: ugyanazt az exportot elkészítjük R-ben, és összevetjük a Python-exporttal. Ha a kettő egyezik, az rdata-ban megbízhatunk.

Kiinduló eset: két export, egy összevetés 
Rscript scripts/asnr_export.R                 # -> data/asnr_r/
Kész: 52 adatkészlet -> data/asnr_r
uv run python scripts/compare_exports.py data/asnr_r data/asnr
105 mátrix összevetve, 0 eltérés.

A 105 mátrix (hálók és ábraadatok) mind cellára egyezik, a címkékkel együtt. Az R-szkript lényege egy ciklus: data(package = "xUCINET") felsorolja az adatkészleteket, és mindegyik minden mátrixát write.csv-vel kiírja. (A teljes szkript: scripts/asnr_export.R a kód mappájában.)

Előkészület a 16. leckéhez 
Rscript -e 'install.packages(c("statnet", "RSiena"))'
Rscript -e 'library(ergm); library(RSiena); packageVersion("ergm"); packageVersion("RSiena")'

A statnet egy csomaggyűjtemény (benne az ergm, a network és a sna). Kipróbáláskor (2026. november, R 4.6.2) az ergm 4.12.0 és az RSiena 1.6.6 települt. Ha később Pythonból akarod hívni őket, arra az rpy2 való. Ez opcionális: a 16. leckében az R-kódot külön futtatjuk, és CSV-n át adjuk vissza az eredményt.

✏️ Gyakorlás – ellenőrzés
  1. Az összevetés 0 eltérést ad. Jelenti ez, hogy a könyv adatai hibátlanok?
    MegoldásNem. Csak azt, hogy az rdata pontosan azt olvassa ki, amit maga az R. A metaadat-hibák (0.4) mindkét exportban benne vannak.
  2. Miért nem hasonlítjuk össze a networkinfo.csv-ket is?
    MegoldásMert a logikai értékeket a két nyelv másként írja ki (R: TRUE, Python: True), így szöveges eltérés lenne tartalmi eltérés nélkül. A számszerű mátrixok összevetése a lényeg.
  3. (nehezebb) Mi szól amellett, hogy a 16. leckében az R-kódot külön futtasd, és ne rpy2-vel Pythonból?
    MegoldásAz rpy2-nek nincs kereke, forrásból fordul (R-fejlécek kellenek hozzá), és a két nyelv adattípusainak átalakítása újabb hibaforrás. Egy R-szkript + CSV egyszerűbb, átláthatóbb, és ugyanúgy reprodukálható.
